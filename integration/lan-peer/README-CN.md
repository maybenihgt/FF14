# UU 云联机四客户端名单与公共牌局同步测试版

## 使用方法

1. 在最多四台电脑上手动加入同一个 UU 云联机房间。
2. 在插件主窗口切换到 **多人模式**。
3. 每台电脑的账号类型默认是 **小号**；只有主动选择 **大号** 才会广播为大号。
4. 每台电脑开启 **加入四人桌 / 启用节点发现**。
5. 如需同步公开牌面，再单独开启 **向局域网同步公开牌局状态**。
6. 在 Windows Defender 防火墙的“专用网络”配置文件中允许 UDP 入站端口 **47721** 和 **47722**。
7. 等待几秒钟，名单显示同一可见 IPv4 子网内其他插件实例；公共状态区显示已收到的客户端桌面状态。

不再需要插件自己的共享房间码。UU 云联机房间由用户手动加入；插件通过 IPv4 UDP 广播发现同一可见子网内的插件实例。

## 大号 / 小号身份

- 默认身份是 **小号**。
- 只有用户主动点击 **大号**，该客户端才会以大号身份广播。
- 不再使用 MAIN_A、MAIN_B、ALT_C、ALT_D 等账号标签。
- 身份仅用于本地界面和在线名单标记，不是账号凭据。

## 公共牌局状态同步

每台客户端可以单独选择是否广播自己的公共牌局状态。广播内容仅包含：
- 当前局风、局数、本场和立直棒
- 四家当前公开分数
- 四家可见牌河及牌河标记
- 四家公开副露、立直状态
- 宝牌指示牌、剩余牌墙、巡目

为避免泄露隐藏信息，UDP 47722 的数据白名单**不包含**：
- 本机暗手牌及暗手牌中的赤牌身份
- 摸牌结果、可操作动作列表
- AI 推荐、Mortal 决策
- 里宝牌或其他私有信息

每台客户端仍在本机单独分析自己的手牌。公共牌面同步只用于让四台电脑对公开牌局信息进行核对，不会合并本机 AI 决策，也不会控制其他客户端。

状态同步要求本机已有通过一致性校验的公共状态。国服协议捕获或牌桌映射尚未就绪时，客户端不会广播未验证状态。

## 四人名单与实际麻将对局的区别

当前多人页提供的是最多四个客户端的在线名单和公开牌面镜像，不是独立的麻将游戏服务器。真正的麻将对局仍在 FF14 游戏内开始和运行。

旧的 backend/team_room.py 是独立的 2v2 私人沙盒/积分测试原型，只接收手动提交的 JSON 快照和赛后积分，不是本插件的实时四人牌局服务。

## 网络范围与安全边界

- UDP 47721：在线节点发现。
- UDP 47722：可选公共牌局状态广播。
- 两种广播都限制在本机检测到的 IPv4 子网；同一可见子网的其他插件实例也可能出现。
- 这些广播不使用共享房间密钥或密码学身份认证，因此仅应在你信任的 UU 虚拟局域网中使用。
- 接收端对消息长度、分片数量、时间戳、座位、牌值和数据数组长度进行校验；收到的数据只用于显示公共状态。

## 故障排查

- 确认所有电脑确实加入了同一个 UU 云联机房间。
- 确认每台电脑都启用了节点发现；要共享公共牌面，还要额外开启公共牌局状态同步。
- 确认 Windows 防火墙允许专用网络 UDP 47721 和 47722 入站。
- 如果两台电脑可以互相 ping，但列表或状态仍为空，可能是 UU 虚拟网卡没有转发 IPv4 广播；届时需要增加单播发现回退方案。
- 节点和公共状态超过 8 秒没有心跳会从列表中消失。
- 两台客户端必须都运行包含相同公共状态协议的插件版本。

## 尚未实现

- 不同步隐藏手牌，不把四家暗手牌拼成全知牌局。
- 不跨客户端转发 AI 推荐、舍牌决策或自动操作指令。
- 不创建独立四人麻将服务器，也不改变 FF14 的实际牌局。
